\section{Executive summary}

The editing model must solve two distinct problems:

\begin{enumerate}
  \item \textbf{Grounding:} identify which SVG node corresponds to the object
  described by the user.
  \item \textbf{Editing:} apply a valid operation to that node, such as changing
  fill, adding a contour, or removing the element.
\end{enumerate}

An ordinary protected DOM skeleton exposes structure, tags, styles, and safe
geometry summaries, but it intentionally replaces heavy path coordinates with
hashes. A language model can therefore see that four nodes are red paths
without knowing which one is at the top-left. The implemented treatment closes
that gap by measuring each node's visible contribution and adding a small
\code{visual} object to its existing JSON record.

\boxnote{green}{
  \textbf{The node-hiding operation is a measurement trick, not the edit.}
  A temporary copy of the SVG is rendered with one node hidden. The pixel
  difference from the full render describes that node. The temporary SVG is
  discarded. The model later emits a patch, and the executor applies that patch
  once to the original SVG.
}

The control and treatment share the same model, prompt function, scene
serialization, parser, validator, executor, dataset order, and evaluator. The
only treatment change is the attached \code{visual} field. This makes the
experiment an interpretable A/B test of additional semantic grounding context,
not a comparison between unrelated editing systems.

The small diagnostic experiments show that the measurements contain usable
information. The 10-case smoke improved exact targets from 70\% to 90\%; an
8-instruction path-only pilot improved from 0\% to 75\%; and the 39-source
controlled holdout improved exact targets from 7.7\% to 33.3\%. The holdout
had 10 visual-only paired wins and no skeleton-only wins.

The completed official matrix changes the system conclusion. Across 500
matched cases per arm, exact target selection fell from 56.4\% to 48.8\%,
exact patch match fell from 19.2\% to 17.8\%, valid output fell from 55.2\% to
52.0\%, and failure-aware MSE rose from 0.4538 to 0.4886. On the 200
node-grounding cases, exact targets fell from 79.5\% to 66.0\%. The treatment
did yield small gains on some root-only operations, especially transparency and
upside-down edits.

Three follow-up analyses then took that headline apart. A mediation analysis
showed the exact-target metric was absorbing output failures: 65 of the 78
skeleton-only wins are cases where the treatment emitted no parseable patch or
an unrenderable SVG, and only 13 are valid patches aimed at the wrong node. An
audit of the retained call metadata then found why. Prompts above roughly
4,096 tokens were being silently truncated, the treatment's longer prompts
crossed that limit 3.6 times as often, 90 cases against 25, and every
truncated call failed. On the 410 cases where both arms received a complete
prompt, the same run reads \(-2.7\) points at \(p=0.294\).

A re-run with schema-constrained decoding closes the argument. Responses with
no parseable patch fall from 103 to one, both arms gain 8 to 12 points of
exact-target accuracy, failure-aware raster error falls by 25\% and 31\%,
and completion tokens equalise, confirming the earlier 68\% excess was
malformed continuation rather than work. The remaining overall gap is 3.6
points at \(p=0.057\).

What survives is a genuine grounding cost, smaller than the headline and
larger than the mediation estimate. On the 200 grounding cases, where both
arms now reach 100\% valid output, the treatment loses 5.5 points across 18
paired losses that are all well-formed patches aimed at the wrong node, and
the effect is concentrated in \code{change_color}. Render-derived context
should therefore be routed through a constrained, instruction-gated ranking
stage rather than appended to every prompt, and constrained decoding should be
the default for both arms. The benefit side remains unmeasured here, because
no instruction in this benchmark asks for the position or size the visual
fields describe.

\section{Problem statement}

\subsection{Why SVG source alone is not always enough}

SVG source is structured, but the structure is not equivalent to visual
meaning. A node may be:

\begin{itemize}
  \item a path whose coordinates are intentionally hidden from the model;
  \item nested under inherited styles and transforms;
  \item partly or fully covered by a later-painted element;
  \item one of several nodes with the same tag and color; or
  \item visible only through a small, anti-aliased region.
\end{itemize}

For an instruction such as ``add an outline to the small red shape in the
top-left,'' a protected skeleton may expose four indistinguishable red
\code{path} nodes. DOM order is not a reliable spatial description. A whole
rendered image tells the model what the composition looks like, but it does not
establish a deterministic link from image pixels back to node IDs. The required
context is therefore \emph{per-node visual attribution}.

\subsection{Scope of this work}

This report evaluates a lightweight method for selecting existing nodes. It
does not claim to solve full semantic segmentation, raster-to-SVG generation,
or arbitrary reconstruction of missing geometry. The principal question is:

\begin{quote}
\emph{If every SVG node carries compact render-derived information about what
it contributes, can a frozen text-only model ground natural-language editing
instructions more accurately?}
\end{quote}

\section{Relationship to LayerSVG}

LayerSVG studies a different but adjacent problem: converting a raster image
into complete, semantically separate, independently editable SVG layers
\cite{layersvg}. Its top-down elimination pipeline selects foreground masks,
inpaints regions hidden behind them, and then vectorizes the recovered layers.
The paper emphasizes two properties that are directly relevant here:

\begin{itemize}
  \item edits should operate on semantically meaningful objects rather than
  isolated strokes; and
  \item a lower layer should be complete, so moving or deleting an upper layer
  does not reveal a hole.
\end{itemize}

Those principles clarify the boundary of our approach. Render-difference tags
can identify \emph{which existing node} is the cloud and how it appears. They
cannot recover sun geometry that was never present in the source. LayerSVG uses
generative inpainting while constructing editable layers; SVGPatchLab starts
from an existing SVG and performs a surgical edit. For the latter, generation
should be an exceptional completion step, not the default node-selection
mechanism.

LayerSVG also provides a useful efficiency precedent in its stroke-reduction
analysis: it assigns a unique RGB identifier to each stroke, composites the
layers, and counts which identifiers remain visible. SVGPatchLab already has a
related ID-buffer implementation. For safe, opaque SVGs, one normal render and
one unique-color render can recover leaf ownership, bbox, area, position, and
observed color in a total of two rasterizations, independent of node count.
Opacity, blending, filters, masks, and other unsupported effects route to the
more general hide-and-diff method.

\section{Method}

\subsection{Counterfactual visual measurement}

Let \(R(S)\) be a deterministic rasterization of SVG \(S\), and let
\(S\setminus n_i\) be a temporary copy in which node \(n_i\) is forced to
\code{display:none!important}. For a pixel \(p\), the contribution mask is

\[
M_i(p) = \mathbf{1}
\left[
  \left\lVert R(S)(p) - R(S\setminus n_i)(p)\right\rVert_\infty > \tau
\right].
\]

The implementation uses a 64 by 64 transparent render for compact measurement.
From \(M_i\), it calculates:

\begin{itemize}
  \item \textbf{bbox}: the affected pixel bounds projected into SVG viewBox
  coordinates with \code{preserveAspectRatio} letterboxing accounted for;
  \item \textbf{area\_pct}: the percentage of the canvas affected by hiding;
  \item \textbf{position}: a coarse spatial label derived from the contribution
  centroid, such as top-left, center, or bottom;
  \item \textbf{color}: a quantized RGB mode over contributing pixels; and
  \item \textbf{visible}: false when no unique pixel delta exceeds the
  threshold.
\end{itemize}

All measurements are cached by SVG content, render parameters, and a versioned
format key. A full SVG is rendered once and each eligible node is hidden and
rendered once on a cold cache. Subsequent uses read the attached statistics from
disk.

\subsection{What the model sees}

The heavy path coordinates remain protected. The new information is a compact
field attached to the node that already has a stable ID:

\begin{lstlisting}[style=compact,language={}]
{
  "id": "n7",
  "parent": "n0",
  "tag": "path",
  "attributes": {"fill": "#ff0000"},
  "protected_geometry": {
    "d": {"sha256": "...", "characters": 20}
  },
  "resolved_style": {"fill": "#ff0000"},
  "visual": {
    "bbox": [5.0, 5.0, 10.0, 10.0],
    "area_pct": 1.0,
    "position": "top-left",
    "color": "#ff0000"
  }
}
\end{lstlisting}

The model receives the instruction and the JSON skeleton as text. It matches
phrases such as ``small,'' ``red,'' and ``top-left'' to the fields, emits a
patch targeting \texttt{n7} with stroke \texttt{\#000000}, and the existing
validator and executor apply that patch to the unmodified source.

\subsection{Meaning of \code{visible:false}}

\code{visible:false} means only that hiding the node caused no measurable
unique pixel contribution at the selected resolution and threshold. It is
useful as weak negative evidence, but it is not proof that the node is
semantically irrelevant or fully occluded. The same observation can arise when:

\begin{itemize}
  \item an identical-colored overlayer masks the change;
  \item the visual effect is below the raster threshold;
  \item the node is extremely small or faint; or
  \item a renderer does not reproduce an SVG feature faithfully.
\end{itemize}

\subsection{Recommended production strategy}

The current recommended measurement design is a hybrid, not a universal use of
either method:

\begin{table}[H]
\centering
\caption{Recommended visual-attribution strategy for an SVG with \(N\) nodes.}
\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{31mm}>{\raggedright\arraybackslash}p{25mm}YY@{}}
\toprule
\textbf{Path} & \textbf{Render cost} & \textbf{Use when} & \textbf{Role}\\
\midrule

\end{tabularx}

The current reported A/B intentionally retains the hide-and-diff treatment to
keep its meaning fixed across all pilot results. The ID-buffer fast path should
be introduced as a separately named treatment and tested for descriptor
equivalence before it replaces the slower cache fill in production.

The completed official matrix also changes how the resulting fields should be
consumed. Attribution can be measured and cached broadly, but the four visual
fields should not be appended to every patch-planning prompt. They should be
activated only when an instruction requires ambiguous node grounding, then
consumed by a constrained target-ranking stage whose selected IDs are passed to
the patch planner.

\section{Clean A/B boundary}

The treatment architecture inherits from the control and overrides only
\code{scene_for()}. Both arms use:

\begin{itemize}
  \item the same prompt template and JSON serialization;
  \item the same Qwen 2.5 7B model configuration and deterministic temperature;
  \item no image input, including when the adapter advertises image support;
  \item the same patch parser, policy, validator, and executor;
  \item the same cases in the same order; and
  \item the same structural and raster evaluators.
\end{itemize}

Regression tests strip \code{visual} from the treatment scene and assert exact
equality with the control scene. They also assert identical request metadata,
absence of image payloads, and identical SVG output when the model response is
held fixed. Consequently, observed differences can be attributed to the
additional text fields, subject to normal nondeterminism in the serving stack.

\boxnote{orange}{
  \textbf{Excluded comparison.}
  \code{visual_skeleton_patch} sends a whole rendered image and is not the
  treatment evaluated here. Including it would change both input modality and
  architecture, destroying the one-variable A/B boundary.
}

\section{Sun and cloud case study}

The sun-cloud example separates node grounding from geometry completion.

\subsection{Case A: the sun is structurally complete}

If the SVG contains a full sun circle painted below a cloud, the correct edit is
simply \code{remove_element(cloud)}. The hidden part of the sun already exists;
normal SVG painter order reveals it after cloud removal. A generator is
unnecessary and could damage unrelated geometry.

\subsection{Case B: the sun geometry is incomplete}

If the sun was flattened, clipped, merged with the cloud, or authored only as a
visible crescent, removal exposes a hole. The node selector can still identify
the cloud, but the existing source does not contain enough geometry to restore
the missing region. This is where a small generator can be useful.

The implemented completion path is deliberately conservative:

\begin{enumerate}
  \item select candidate nodes using per-node semantic and visual context;
  \item apply the requested deletion;
  \item trigger completion only when deletion creates a sufficiently large
  transparent hole rather than revealing a valid underlayer;
  \item ask Qwen to replace one preserved reconstruction candidate with one SVG
  element; and
  \item accept the candidate only if it preserves the canvas, contains no unsafe
  SVG features, does not restore the deleted element, changes the intended
  region, and stays below an outside-region error threshold.
\end{enumerate}

In the live smoke artifact, the final stored SVG contains a completed circle
centered at (18, 18), with radius 10 and fill \texttt{\#FFAC33}. The accepted
attempt reported outside-region MSE 0.00178 against a maximum of 0.01, while its
inside-region and generated-change checks exceeded their minimum thresholds.
This is a useful mechanism check, not yet a quantitative completion benchmark.

\subsection{Metrics}

The primary grounding metric is exact equality between the set of target node
IDs in the predicted patch and the gold target set. Additional metrics are:

\begin{itemize}
  \item target precision and recall;
  \item exact equality with the gold patch signature, including operation,
  target set, and attributes, rather than byte-for-byte JSON equality;
  \item valid SVG output rate;
  \item failure-aware raster mean squared error (MSE), where lower is better
  and a missing, invalid, or unrenderable output receives 1.0;
  \item paired wins and losses on the same case; and
  \item prompt-token and model-latency cost.
\end{itemize}

\subsection{Official smoke}

The official smoke uses 10 matched SVGEditBench task cases: two each from color
change, contour, upside-down, transparency, and crop. These cases reuse two
unique source SVGs across five instructions, so they are not 10 independent
visual samples. The smoke checks compatibility across the normal task mix, but
only four task cases are node-grounding tasks.

\subsection{Completed official matrix}

The full paired matrix contains 500 cases per arm: 100 cases each for color
change, contour, crop-to-half, transparency, and upside-down edits. The same
100 source SVGs recur across the five task families, so the run contains 500
matched task cases but 100 unique visual sources. Color change and contour form
the 200-case node-grounding group. Crop, transparency, and upside-down are
300 root-only controls whose correct target is the SVG root; they test whether
extra node metadata disrupts operation planning and output validity.

Both arms ran sequentially in fixed order on the same server. Paired accuracy
and error comparisons are therefore direct within each case, while latency is
reported descriptively because server load and arm order were not
counterbalanced.

\subsection{Path-only spatial probe}

The probe was constructed to remove baseline shortcuts:

\begin{itemize}
  \item four nodes are all \code{path} elements with the same red fill;
  \item each protected \code{d} string has the same character count;
  \item coordinates are exposed only as opaque hashes;
  \item two unique DOM layouts permute the mapping between node order and
  position; and
  \item each instruction selects one of the four corners.
\end{itemize}

This probe directly asks whether the treatment exposes spatial information
unavailable in the control context.

\subsection{Expanded 39-source holdout}

The expanded suite removes the pilot's source-reuse weakness. It contains 39
matched cases and 39 distinct source SVGs:

\begin{itemize}
  \item 27 position cases cover all nine labels in the 3 by 3 spatial grid,
  with three independently generated sources per label;
  \item 12 size cases cover smallest, second-smallest, second-largest, and
  largest, again with three sources per label;
  \item every source uses a distinct deterministic DOM permutation, balanced
  target-node indices, small coordinate jitter, and aspect variation;
  \item all candidates remain same-fill \code{path} nodes, raw coordinates are
  SHA-only, and every protected path string has the same character count; and
  \item a manifest freezes seed 20260725, prompt v4, the prompt-template hash,
  source and answer hashes, and the expected target for every case.
\end{itemize}

Runtime validation fails closed if a target crosses its spatial bin, relative
size order changes, path coordinates leak, or the active prompt differs from
the frozen version.

\subsection{Prompt sensitivity}

A shared experimental prompt explicitly instructed the model to combine visual

\subsection{A context-window confound in the official matrix}
\label{sec:truncation}

Re-reading the retained \code{model_call_details} while preparing the
constrained re-run exposed a defect in the official matrix that neither the
original analysis nor Section~\ref{sec:mediation} accounted for.

Reported prompt-token counts are not well behaved at the top of the size
distribution. Cases whose prompts fit report plausible varying counts up to
4{,}035 tokens. Above that, counts collapse to \(2{,}050\) or \(0\), values
far too small for the text sent. The same cases in the re-run report 4{,}241
to 4{,}874 tokens. The boundary and the constant are consistent with a
4{,}096-token context limit truncating the serialized scene mid-JSON.

Truncation is identified by comparing the reported count against the prompt
actually sent rather than by matching those constants, because one case
legitimately tokenizes to 2{,}050. Intact prompts in this run span 2.78 to
3.66 characters per reported token and truncated ones 5.76 to 6.18, so a
threshold of 4.5 separates them with roughly 20\% margin either side. By that
criterion 25 skeleton calls and 90 visual calls were truncated.

Every one of those calls failed. All 25 and all 90 produced no patch, no valid
output, and no correct target. They account for 25 of the skeleton arm's 39
no-patch failures and 90 of the visual arm's 103. The RFC 6902 drift
catalogued in Section~\ref{sec:mediation} is therefore concentrated almost
entirely in truncated prompts: a model shown a scene cut off mid-structure
falls back to the patch dialect it knows.

This matters for the A/B because the treatment's prompts are longer by
construction, so more of them crossed the limit: 90 cases against 25, a factor
of 3.6. Restricting the official matrix to the 410 cases where both arms
received a complete prompt changes the headline result.

\section{Interpretation}

\subsection{What the evidence supports}

The render-derived measurements contain real spatial information. When the
ordinary skeleton deliberately removes coordinate shortcuts and the instruction
names position or relative size, the controlled 39-source holdout improved
exact targets by 25.6 points, with 10 visual-only wins and no skeleton-only
wins. This establishes mechanism validity: the hide-and-compare payload can
connect visual descriptors to stable node IDs.

The completed official matrix establishes a second, equally important result:
the usefulness of the measurement does not imply that unconditional prompt
injection improves a general patch planner. In the fixed model and dataset,
target accuracy, exact patches, validity, and failure-aware raster error all
moved against the treatment overall.

Two follow-up analyses then narrowed what that regression means, and the
second corrected the first.

The mediation analysis showed the measured cost was dominated by output
format compliance rather than node selection. The truncation audit
(Section~\ref{sec:truncation}) then explained why: the treatment's longer
prompts crossed a 4{,}096-token context limit 3.6 times as often as the
control's, and every truncated call failed. On complete prompts alone the
official matrix reads \(-2.7\) points at \(p=0.294\), not \(-7.6\) at
\(p=0.00060\).

The constrained re-run (Section~\ref{sec:constrained}) confirms this from the
other direction. With decoding pinned to the patch schema, unparseable
responses fall to zero, both arms gain 8 to 12 points of exact-target
accuracy, and the remaining gap is \(-3.6\) points overall at \(p=0.057\).

What survives is smaller than the headline and larger than the mediation
estimate. On the 200 grounding cases, where both arms now reach 100\% valid
output, the treatment loses 5.5 points, 18 paired wins against 7,
\(p=0.043\). Every one of those losses is a valid patch aimed at the wrong
node, and the effect is concentrated in \code{change_color}. The defensible
statement is therefore that most of the original regression was an artifact
of context truncation and format drift, and that beneath it lies a genuine
but smaller grounding cost on one task family.

\subsection{What the evidence does not support}

The evidence does not support deploying \code{visual_stats_patch} as the
universal replacement for \code{skeleton_patch}. The four fields compete with
operation constraints and patch-format instructions inside a limited 7B
model's context. More context is not automatically better context.

The current fields do not provide object names such as ``cloud,'' ``sun,'' or
``tree.'' They make words like ``small,'' ``red,'' and ``top-left'' groundable.
Semantic object recognition still comes from tag/style clues, composition,
future learned labels, or a separate vision-language stage. Likewise,
counterfactual rendering measures visible contribution, not the complete
amodal shape of an occluded object. The 33.3\% held-out exact rate also shows
that metadata availability is not equivalent to reliable model use.

\subsection{Efficiency}

In the unconstrained run, the treatment used 1,212,938 prompt tokens versus
1,091,351, an 11.1\% increase, and completion tokens increased 68.2\%. Both
figures are now known to be distorted: truncated calls under-report their
prompts, and the completion excess was malformed continuation rather than
work. The constrained re-run gives the clean measurement. Prompt tokens are
1,491,227 against 1,170,922, a \textbf{27.4\%} increase, which is the real
context cost of the four visual fields once nothing is silently cut off.
Completion tokens are within 0.3\% of each other. Mean latency is 1.27 against
1.16 seconds; the arms still ran sequentially, so latency remains descriptive.

Rendering cost is front-loaded and cacheable. For repeated instructions on the
same SVG, the warm-cache cost is a JSON lookup rather than a fresh render per
node. Cold-cache and warm-cache preprocessing time should be reported
separately when the ID-buffer and guarded-ranking architectures are compared.

\section{Limitations and failure modes}

\begin{enumerate}
  \item \textbf{Repeated official sources.} The full matrix has 500 task cases
  per arm but 100 unique source SVGs reused across five task families. Paired
  case counts must not be interpreted as 500 independent visual samples.
  \item \textbf{Fixed model, prompt, and arm order.} The result is one
  temperature-zero run of Qwen 2.5 7B with skeleton first and visual second.
  Model generality and causal latency require replication and counterbalancing.
  \item \textbf{Synthetic holdout.} Its ambiguity is controlled, but all
  candidates are generated red paths under one contour task and one prompt
  wording. It does not capture the object, compositing, and authoring diversity
  of real SVGs.
  \item \textbf{The unconstrained matrix is not a clean instrument.} Its
  headline result combined three effects: context truncation that hit the
  longer-prompted arm 3.6 times as often, format drift toward RFC 6902, and a
  genuine grounding difference. Only the third is about the treatment's
  hypothesis. Constrained decoding removes the second and eliminates the
  first for these inputs, but the original 500-case numbers should not be
  quoted without that qualification.
  \item \textbf{Silent truncation was not detected at run time (now fixed).}
  Nothing in the harness flagged a prompt that exceeded the server's context
  window; the failure surfaced only as an unusual token count during a later
  audit. The adapter now compares reported prompt tokens against the text
  actually sent and raises \code{PromptTruncatedError} when the ratio implies
  the server saw less than was given. Architectures deliberately let it
  propagate rather than recording it as a model mistake, so a misconfigured
  context aborts the run instead of being scored as a wrong answer. Replayed
  against all 1,000 retained calls the check flags 115 of the 115 truncated
  ones with no false positives. It remains a heuristic: a tokenizer with
  markedly larger tokens would need \code{max_chars_per_prompt_token} raised.
  \item \textbf{Conditioning on a post-treatment variable understated the
  effect.} The mediation analysis conditions on \code{valid_output}, which the
  treatment affects, so the both-valid subset is selected rather than
  randomized. Its 2.2-point residual estimate for the grounding group proved
  optimistic against the 5.5 points measured directly under constrained
  decoding, though its per-task pattern held exactly.
  \item \textbf{Unique contribution, not full shape.} The difference mask
  describes pixels that change when a node is hidden. Covered regions are not
  recovered.
  \item \textbf{Raster sensitivity.} Very small, faint, filtered, or
  anti-aliased features can fall below the measurement threshold at 64 pixels.
  \item \textbf{Renderer fidelity.} Filters, masks, blend modes, markers,
  external resources, and fonts can vary across renderers.
  \item \textbf{Groups and ownership.} Hiding a group can measure the union of
  descendants, while hiding one leaf measures only that leaf. Prompts must not
  confuse containment with semantic identity.
  \item \textbf{No learned object labels.} Nodes with similar color, area, and
  position remain ambiguous when the instruction names an object class.
  \item \textbf{Generation risk.} A completion model can hallucinate,
  duplicate, or shift geometry. It must remain trigger-gated and
  validator-gated.
  \item \textbf{Incomplete system provenance.} The holdout manifest records the
  seed, prompt hash, source hashes, and expected targets, but hardware, git
  commit, cache state, and server load still need automatic capture.
\end{enumerate}

\section{Next steps}

The constrained re-run has completed, so the prerequisite is discharged and
the list is reordered around what it left standing:

\begin{enumerate}
  \item \textbf{Measure the hypothesis on instructions that can test it.} All
  200 grounding instructions in this benchmark identify their target by fill
  color, which the ordinary skeleton already carries, and the remaining 300
  address the root. No case requires the position or size the visual fields
  supply, so the treatment's ceiling here is a tie and its floor is the
  27.4\% context cost now measured cleanly. A held-out set of natural
  position- and size-naming instructions over real authored SVGs is the only
  way to observe a benefit, and is now the blocking experiment;
  \item \textbf{Diagnose \code{change_color}.} It carries essentially the
  whole surviving regression, 87\% to 77\%, while \code{set_contour} under an
  identical scene loses one point. Both arms reach 100\% valid output there,
  so this is a pure selection effect and should be readable from the 18 paired
  losses;
  \item gate visual context by instruction type, omitting it for root-only
  operations, whose exact-target scores carry no grounding information once
  output is valid;
  \item separate target ranking from patch planning: a constrained first stage
  returns only node IDs, then the existing planner receives those IDs and the
  instruction without the full visual payload;
  \item fix the remaining root-only failures, which are now the largest single
  block: 31 of the 49 paired losses are patches that parse and validate but
  render an invalid SVG, concentrated in crop and transparency;
  \item ablate compact descriptors, including size rank and numeric centroid,
  instead of assuming the current four-field block is optimal;
  \item benchmark the two-render ID-buffer fast path against hide-and-diff for
  descriptor equivalence, preprocessing speed, and unsupported-feature
  fallback;
  \item repeat the paired matrix with counterbalanced arm order, multiple
  seeds, natural grounding instructions, partial overlap, groups, and real
  authored path shapes; and
  \item construct a deletion/completion benchmark with known complete and
  incomplete underlayers, recording cold-cache and warm-cache timing.
\end{enumerate}

\section{Conclusion}

Render-derived attribution is a useful measurement, but unconditional visual
metadata injection is not the production solution. The controlled holdout
proved that bbox, area, position, and color can recover spatial information
hidden by the protected skeleton. The completed official matrix then showed
that feeding those fields to every Qwen patch request reduced exact target
selection from 56.4\% to 48.8\% and increased model cost. Two audits have
since established that most of that gap was instrumentation rather than
grounding.

The longer treatment prompt crossed a 4{,}096-token context limit 3.6 times as
often as the control's, and every truncated call failed outright. Excluding
those cases, the same run reads \(-2.7\) points at \(p=0.294\). Re-running
under schema-constrained decoding, unparseable responses fall from 103 to one,
both arms gain 8 to 12 points of accuracy, failure-aware raster error drops by
25\% and 31\%, and the remaining gap is \(-3.6\) points at \(p=0.057\).

A real effect does survive, smaller than the headline and larger than the
mediation estimate. On the 200 grounding cases, with both arms now at 100\%
valid output, the treatment loses 5.5 points, and every one of those 18 paired
losses is a well-formed patch aimed at the wrong node. The cost is
concentrated in \code{change_color}; \code{set_contour} loses one point.

The recommended route remains a guarded pipeline: measure and cache
attribution, invoke it only when the instruction requires ambiguous node
selection, resolve candidate IDs with a constrained ranking stage, and pass the
selected IDs to the ordinary patch planner, with root-only operations bypassing
the visual payload. Constrained decoding should now be the default for every
arm, since it improved the control as much as the treatment.

The honest limit of this evidence is that the benchmark cannot reward the
idea. Every grounding instruction here names its target by fill color, which
the plain skeleton already carries, so the visual fields can only ever cost
27.4\% more prompt context and never repay it. The 5.5-point loss is the price
of irrelevant context, not evidence that render-derived attribution fails at
what the holdout showed it can do. Establishing benefit requires instructions
that name position or size on real authored SVGs, which is the next experiment
rather than a robustness check.

For the sun-cloud example, the decision is now precise. Use render-derived
context to select and remove the cloud. If the full sun exists underneath, stop.
Only when deletion reveals genuinely missing geometry should the guarded Qwen
completion path reconstruct the preserved sun node.
